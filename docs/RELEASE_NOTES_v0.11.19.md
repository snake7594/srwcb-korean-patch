# v0.11.19 — EX 점검·수정 (제2차·제3차에서 배운 것 전부 적용)

제2차·제3차를 고치며 알아낸 것들을 EX에 그대로 대어 보고, 걸린 것을 모두 고쳤습니다.
같은 검사에서 제2차·제3차에도 남아 있던 문제가 나와 함께 손봤습니다.

## EX에서 찾아 고친 것

### 1. 대사에서 띄어쓰기가 통째로 사라지던 문제 (295건)

한 줄이 한 칸 모자랄 때 축약기가 **띄어쓰기를 전부 지워** 버리고 있었습니다.
EX는 긴 대사가 많아 특히 심했습니다(긴 대사의 7.2%).

```
전  골드「소인은골드바골드라고합니다.지금이야산적따위를하고있습니다만,…
후  골드「소인은 골드바골드라고 합니다.지금이야 산적 따위를 하고 있습니다만,…
```

축약 사다리에 **부분 제거 단계(10~90%)** 를 넣어, 모자라는 만큼만 지웁니다.
지우는 자리는 눈에 덜 띄는 곳(구두점 뒤 → 짧은 토막 사이) 부터 고릅니다.
세 게임 모두 적용됩니다.

### 2. EX 갭 주입기에 축약이 아예 없던 문제

원장 밖 보충 대사는 축약 단계를 한 번도 거치지 않아, 안 들어가면 그대로 넘쳤습니다.
같은 사다리를 쓰도록 했습니다.

### 3. 폭 18 시절의 낡은 축약 원복

대사창이 **폭 32**로 확정되기 전에 폭 18 기준으로 줄여 놓은 선택지 문구를 되돌렸습니다.

```
전  마사키「입이 살았군‥‥」/ 말없이 강타
후  마사키「호오, 아직 그런 말이 나오나‥‥」/ 말없이 후려친다
```

### 4. 작전목적(승리/패배조건) 블록 보호

제3차에서 이 블록이 원문 배치를 벗어나면 승리조건이 비고 패배조건에 엉뚱한 대사가
들어왔습니다. EX도 같은 계열 엔진이라 같은 보호를 겁니다(조건문 8개, 13바이트 조정).

## 세 게임 공통으로 고친 것

- **레코드 경계 안정화가 여유 없는 레코드에도 공백을 붙이던 버그**
  거부값을 무시하는 폴백 때문에 그 줄이 상자를 한 칸 넘었습니다(EX `0xA73C2` 적발).
  이제 여유가 없으면 손대지 않고, 앞이 막혔으면 **뒤쪽** 레코드에서 여유를 찾습니다.
  덕분에 오래 남아 있던 경계 불일치가 전부 해소됐습니다.
  - 제2차 시나리오 4 → 해소
  - EX 시나리오 8·23·52·55 → 해소
- **채움 바이트가 마지막 줄을 넘기던 문제** — 여유 있는 줄에 나눠 넣습니다
- **쪽 나눔 경로의 폴백이 가장 넓은 후보를 고르던 문제** — 가장 좁은 후보를 씁니다

## 검증

세 게임 × (컴플리트 박스, 단독판) 6개 이미지 전부:

```
미번역 0 / 대사창 폭·줄 초과 0 / 작전목적 블록 0 / 깨진 레코드 0
레코드 경계 불일치 0
```
