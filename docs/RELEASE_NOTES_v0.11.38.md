**EX 에서 전투가 끝나고 맵으로 돌아오면 커서가 사라지고 아무 입력도 안 먹던 것**을
고쳤습니다. 멈춘 순간의 세이브스테이트를 받아 RAM 을 직접 읽고 확정했습니다.

같은 원인이 **제2차·제3차·EX·컴플리트 박스 전부**에 있었습니다.

## 무엇이 문제였나 — CD 섹터의 EOF 비트

PS1 디스크의 MODE2 섹터에는 2048바이트 데이터 앞에 **8바이트 서브헤더**가 붙습니다.
그 셋째 바이트가 **서브모드**이고 비트7(`0x80`)이 **EOF**(파일의 마지막 섹터)입니다.

```
레트일 데이터 파일:  00 00 08 00 00 00 08 00     ← 모든 섹터
                     00 00 89 00 00 00 89 00     ← 마지막 섹터에만
```

**`CdRead` 는 EOF 섹터를 만나면 거기서 전송을 끝냅니다.**

그런데 우리 이미지 조립기는 **2048바이트 사용자 데이터만 갈아끼우고 옛 서브헤더를
그대로 뒀습니다.** 그래서

- **재배치된 파일**이 남이 비우고 간 자리를 쓰면 그 파일이 찍어 둔 EOF 를 물려받아,
  **파일 한가운데에서 읽기가 끊깁니다.**
- **새로 이어붙인 꼬리**에는 EOF 가 아예 없어 읽기가 파일 끝에서 안 멈춥니다.

실제 상태(v0.11.37):

| 파일 | 섹터 수 | EOF 가 선 위치 | 정상 |
|---|---|---|---|
| `EX/E_SCE.BIN` | 425 | **2, 206** | [424] |
| `BMESS4.BIN` | 382 | **2** | [381] |
| `BMESS3.BIN` | 337 | **2** | [336] |
| `BMESS2.BIN` | 358 | **302** | [357] |
| `SECOND/2_SCE.BIN` | 249 | **229** | [248] |
| `EX/E_DEAD.BIN` 외 4개 | — | **없음** | 마지막 |

`EX/E_SCE.BIN` 의 2번째 섹터 EOF 는 **옛 `SECOND/2_DEAD.BIN` 의 마지막 섹터 플래그**입니다.
v0.11.36 에서 시크 거리를 줄이려고 E_SCE 를 그 자리(LBA 24,715)로 옮긴 결과입니다.
그 전 판들도 무사하지 않았습니다 — 디스크 끝에 이어 붙이던 시절엔 **마지막 섹터에
EOF 가 없어서** 같은 부류로 깨져 있었습니다. 그래서 v0.11.35·36·37 증상이 똑같았습니다.

## 어떻게 확정했나

멈춘 순간의 DuckStation 세이브스테이트에서 2MB RAM 을 꺼내 읽었습니다.

```
PC            0x800F5FF8   VSync 대기 루프
호출 사슬     main -> 0x80062B34 (스크립트 인터프리터) -> VSync 대기
gp+0x28C      0  (옵코드 인덱스)
gp+0x288      0x80199579  (스크립트 바이트 포인터)
```

옵코드표 `[0x00]` 은 기본 핸들러 `0x800628D0` = `return 0x8000` → 카테고리 8 =
**다음 프레임까지 양보**. 즉 스크립트가 **아무것도 안 하고 양보만 무한 반복**합니다.
메인 루프는 살아 있으니 음악은 계속 나고, 커서와 입력은 전부 스크립트가 구동하므로
같이 죽습니다.

`0x80199579` 가 가리키는 곳은 **0 만 있는 빈 힙**이었습니다. RAM 에 올라온
시나리오를 대조하니

```
sc23  RAM 0x8019141C   11,943 / 11,943 바이트 일치  (완전히 로드됨)
sc24  RAM 0x801943D4   앞 0x49 바이트만 있고 나머지 전부 0   ← 읽다 끊김
```

90초 간격으로 뜬 두 번째 세이브스테이트와 비교하니 스크립트 포인터가
`0x80199579 → 0x8019AACD` 로 **프레임당 1바이트씩 기어가고** 있었고, 서브콜 깊이도
`3 → 8` 로 계속 자라고 있었습니다. 회복 불가능한 상태입니다.

CD 파일 캐시(부팅 때 이름으로 찾아 캐시하는 30개 엔트리)는 **LBA·크기 전부
우리 이미지와 정확히 일치**했습니다. 즉 위치는 맞는데 **읽기가 중간에 끊긴** 것입니다.

## 어떻게 고쳤나

조립기가 섹터를 쓸 때 서브헤더를 **항상 다시 씁니다.**

```python
sec[0x10:0x18] = bytes([0, 0, 0x89 if i == n - 1 else 0x08, 0]) * 2
rebuild_mode2_form1(sec)     # EDC 는 0x10(서브헤더)부터 계산한다
```
