## 1. EX 프리즈 (#10 · #11) — 목표가 바뀌는 순간 멈췄다

EX 시나리오 앞머리의 작전목적 블록에는 '2단계 승리조건'(목표 변경) 레코드가 있고,
레트일에서는 반드시 **`04 00 <창폭> 00` 4바이트 이진 헤더**로 시작합니다.

그런데 글리프 `0x00` 은 폰트표에 문자가 없어서 텍스트 추출에서 **통째로 사라집니다.**
반대로 `0x04` 는 `'` 라는 문자가 있어 '첫 글자'로 잡히고, 그 바람에 EX 전용
재인코딩 경로가 레코드 전체를 번역문에서 새로 만들면서 헤더를 `04 <창폭>` 으로
찌그러뜨렸습니다. 레코드 길이는 그대로라 어떤 검사에도 안 걸렸습니다.

그 상태로 목표가 바뀌면 창이 헤더를 잘못 읽고 게임이 멈춥니다.

| EX 시나리오 | 어디서 멈추나 |
|---|---|
| 마사키 9화 (데몬 핵) | 제한시간 뒤 목표 변경 |
| **마사키 11화 (코럴 캐니언·다시)** | **리나 구출 → 목표 변경** ← 제보 #11 |
| 마사키 27화 (결전, 듀라크실) | 목표 변경 |
| **류네 45·49화 (초마장기 에우리드)** | **적 전멸 → 에우리드·발시온 증원 → 적 턴 종료** ← 제보 #10 |
| 슈우 58화 (모니카, 그 사랑) | 목표 변경 |

여섯 곳 전부 헤더를 되살렸습니다. 제보된 두 곳뿐 아니라 **아직 제보 안 된 네 곳**도
같이 낫습니다. 제2차·제3차는 같은 레코드를 제자리 치환만 해서 원래 무사했습니다.

덤으로 같은 블록에서 두 가지를 더 고쳤습니다.

- 시나리오 11 의 1단계 승리조건 `リィナの救出` 가 미번역이라 「リィナの닉낏」로 떴습니다 → `리나구출`
- 슈우 58화 승리조건이 잘려 있었습니다 → `적 전멸/맵 왼쪽 끝 도달`

### (b) 레코드 **안쪽**을 겨누는 포인터가 재조준에서 통째로 빠졌다 (#17 · #18 · #19)

FF 로 끝나는 레코드 하나에 `[F9 02]시스템문` 과 `이름「대사」` 가 같이 들어 있고,
게임이 그 **안쪽 시작 바이트**를 직접 겨누는 자리가 제3차 12곳·EX 45곳 있습니다.
재조준기가 '레코드 시작' 만 참조로 인정해서 이 57곳이 전부 스테일이었습니다.

레코드를 쪼개면 번역 원장이 깨지므로, 배포본 레코드 안에서 **`k번째 「 앞 화자
이름의 시작`을 다시 찾는** 방식으로 고쳤습니다. 화자 이름 사전은 파일이 스스로
만듭니다(레코드 시작 대사 수천 개에서 추출). 57곳 전부 이름 사전으로 확정됐고
'확신 낮음' 은 한 곳도 없습니다.

- 제3차 24화 류네「방해하지 마!…」 → `げ「DC의 부대!?」` 로 나오던 것
- 제3차 26화 코우「어라‥‥뭐지?」 → 빈 상자로 나오던 것
- 제3차 31화 브라이트「서둘러라!…」 → `ゃ브리타임…` 으로 나오던 것

앵커부터 그리는 꼬리는 줄바꿈이 레코드 시작 기준으로 잡혀 있어 첫 줄이 상자를
넘쳤습니다(10곳). 길이를 바꾸지 않고 `00`↔`F6` 만 맞바꿔 다시 나눴습니다.

## 3. 대사가 4픽셀씩 잘리던 것 (#14b · #20a)

커서는 `x = 원점 + 8*칸 + 4*반칸` 으로 움직이는데 전각 잉크는 12px 입니다. 그래서
안 잘릴 조건은 정수 칸이 아니라

```
2 * 칸수 + 줄끝 반칸  ≤  2 * 상자폭
```

입니다. `31칸 + 반칸` 은 정수로는 합격인데 화면에서는 마지막 글자가 **4px 잘립니다.**
코덱도 검사기도 정수만 봐서 이 상태를 계속 통과시켰습니다.

| | 전 | 후 |
|---|---|---|
| 잘리는 대사 | 389개 | **0** |
| 잘리는 전투 대사 | 79줄 | **0** |

`max(원문폭, 31)` 도 같이 고쳤습니다 — 원문이 32~34칸을 쓴 레코드가 있는데 그건
그 줄이 **원문의 첫 줄**이라 들어갔던 것이고, 그 폭을 이어지는 줄에 그대로 허용하면
8px 넘칩니다. 대사창 레코드만 31칸으로 조이고, 폭 40 초과인 특수 레코드 5건은
레이아웃이 달라 예외로 뒀습니다.

## 4. 선택지 항목 경계 (#13 · #21b · #14a)

선택지 레코드의 `F6` 는 **항목 구분자**인데, 우리 빌드가 3줄 예산을 주고 폭 31 로
자유롭게 재래핑해서 항목 하나가 두 줄로 접혔습니다. 선택지 커서는 줄 단위로
움직이므로 하이라이트와 글이 어긋납니다.

항목별로 따로 인코딩하는 경로를 만들고(`translation/choice_options.json`) 13곳의
문안을 항목당 한 줄에 들어가게 다시 썼습니다. 제보에 없던 한 곳(EX 49화 류네)도
같이 잡혔습니다 — 줄 수는 2로 그대로고 **끊는 자리만** 틀린 경우라 줄 수 검사에는
안 걸리던 것입니다.

## 6. 화면 정렬 — 칸이 아니라 **반 칸(4px)** 문제였다

- **#16 유닛 능력 화면 `무기성능`** — 앞 칸 `파일럿능력`(전각 5개)이 반칸을 뒤집어
  놓아서 x 136 → 140 이 되고 상자 오른쪽 테두리를 2px 침범했습니다. 반각 빈칸
  두 개를 전각 빈칸 하나로 바꿔 폭은 그대로 두고 반칸만 되돌렸습니다.
- **#18b · #9 출격 머리글** — `출격유닛남음` 뒤를 반각 빈칸으로만 메워 14칸이어야
  할 것이 15칸이 됐고, `10기`·`기력 100`·`LV순` 이 통째로 8px 밀렸습니다. 게다가
  제2차·SLPS 는 바이트 배치가 달라 그 치환이 **아예 안 맞는데도 조용히 넘어갔습니다.**
  다섯 실행파일 전부 레트일과 같은 14칸/반칸 0 으로 통일했습니다.
- **#9 목록 열 계단 밀림** — v0.11.33 에서 이미 고쳐졌습니다(제보 스크린샷은
  v0.11.31 캡처). 다시 확인해 주세요.

## 8. 무기명 띄어쓰기 (#15a)

띄어쓰기 제거가 '정책' 이 아니라 '폭 초과 구제책' 으로만 걸려 있어서, 폭에 들어가는
**172종**에만 공백이 남아 같은 표에서 표기가 갈렸습니다(`다이탄미사일` 옆에
`다이탄 잔바`). 사전에 추가하는 방식은 전수가 안 됩니다 — 제2차는 그 사전을 아예
안 읽고, 제3차·EX 전용 무기명은 다른 파일에서 옵니다. **주입기 규칙**으로 못박아
네 실행파일 전부 내부 공백 0곳입니다.

무기명 칸은 고정 폭 슬롯이 아니라(주입기가 표를 풀에 재배치하며 포인터를 다시
씁니다) 공백을 빼도 뒤 열이 밀리지 않습니다.

## 9. EX·트레이닝 맵 메뉴 (#21c)

`부대 / 반격 / 목적 / 정신` 으로 잘려 나오던 것을 `부대표 / 반격명령 / 작전목적 /
정신검색` 으로 되돌렸습니다. 사전 문제가 아니라 **레코드 바이트 예산** 문제였습니다
(전체 이름은 +14B 인데 여유는 9~10B). 칸은 남습니다 — `반격명령`(48px)은 레트일
`反撃命令`(48px)과 폭이 같고 같은 창에 이미 `페이즈종료`(60px)가 들어가 있습니다.
제3차·제2차·SLPS 가 이미 쓰던 것과 같은 방식으로 레코드를 폰트 꼬리로 옮기고
포인터를 다시 겨눴습니다.

## 10. 예고 타이틀 카드 그래픽 (#15b · #18c)

제목 스프라이트를 **2바이트(=4픽셀) 늦은 자리**에 읽고 써 왔습니다. 그래서

- 우리가 그린 글자가 오른쪽으로 4px 밀리고, 각 행 끝 4px 이 **다음 행 맨 앞으로 감기고**
- 쓰기의 마지막 2바이트가 늘 **옆 레코드**(영문 자막·작은 숫자) 첫 4픽셀을 덮었습니다
  (52개 레코드 58바이트 — i18_4 의 'WOMAN' 위 대시가 그것입니다)

구조 불변식 두 개가 `-2` 에서만 맞는 것으로 확정했습니다.

```
마지막레코드.off + w*h/2 == 블롭 길이
레코드표 끝 ~ 첫 픽셀 간격 == 4 + 32 * CLUT수
```

## 11. 이름 표기 (#19b)

`푸르/푸르투` 는 저장소·원장·571MB 이미지를 통틀어 **딱 한 곳**, 제3차 예고 타이틀
카드 그래픽뿐이었습니다(대사·로스터는 이미 `플`). `플과 플투와` 로 고치고, 요청하신
표기에 맞춰 `플 투` → `플투` 100곳을 통일했습니다.

> 사전(`glossary_names_ko.json`)에 `"푸르": "플"` 을 넣는 건 하지 않았습니다 —
> 치환기가 단어 경계를 안 봐서 EX 대사의 `카푸르나`(カプル, 수륙양용 MS)가

## 12. 대사가 문장 중간부터 시작하던 것 (#15c)

제3차 사이드1 격투 장면에서 화자 없이 `니에 달라붙어 있는 무사이를,` 부터 나오던
건입니다. 그 상자의 첫 줄이 **첫 줄 원점**(x=55)에서 시작한다는 게 단서였습니다 —
즉 새 쪽의 첫 줄이고, 레코드 앞 8칸(`레코아「콜로`)은 **앞 쪽의 마지막 줄에서 이미
소모**된 것입니다. 엔진이 연속 대사를 3줄 쪽 단위로 이어 그리기 때문에, 번역이
원문보다 줄을 더 쓰면 쪽 경계가 레코드 한가운데로 밀립니다.

그 구간(레코드 9~19)은 원문이 전부 1줄인데 우리 번역이 넷에서 2줄을 썼습니다(+4줄).
그 다섯을 1줄로 다시 써서 원문과 줄 수를 정확히 맞췄습니다.

이 사실이 3번(대사 폭)의 결정에도 영향을 줬습니다 — '레코드 첫 줄은 한 칸 더 써도
된다'는 여유를 **주지 않기로** 했습니다. 레코드의 첫 줄이 실제로는 쪽 한가운데인
경우가 많기 때문입니다.
