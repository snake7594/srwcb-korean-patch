# 전면 재검증 도구 (v0.10.8)

세 게임 + 트레이닝 모드의 한글패치를 **게임이 읽는 경로 그대로** 훑어 남은 문제를
찾는다. 화면에 안 나오는 죽은 사본을 문제로 오인하지 않는 게 핵심이다.

## audit_all.py — 공용 검사 기반
- `sce_records` / `bmess_records` / `dead_records`: 각 아카이브의 레코드 열거.
  BMESS 는 `text_references` 타깃만(=참조되는 것만), DEAD 는 `start != end` 인
  실슬롯만 센다. 안 그러면 빈 슬롯이 다른 레코드 중간을 가리켜 대량 오탐이 난다.
- `line_widths`: 렌더러 규칙(저글리프 1 / 고글리프 phase0=1·phase1=2, F6 개행)으로
  줄별 advance 와 페이지별 줄 수를 계산. 시나리오 폭 18·3줄, 전투 폭 40.
- `decode`: 한글/일본어 매핑으로 레코드를 문자열화.

## 미번역 판정에서 배운 것 (오탐 3단계)
1. **코드 바이트 오탐** — 실행파일 전체를 FF 구분으로 훑으면 MIPS 명령이 가나로
   디코드돼 3,000건 넘게 잡힌다. → 포인터가 가리키는 레코드만 본다.
2. **죽은 사본 오탐** — 번역 후 도너로 옮기고 포인터를 재조준하면 원래 자리에
   일본어가 그대로 남는다. 게임은 안 읽는다. → 번역이 패치본 어딘가에 존재하면
   제외하거나, 테이블/ui_master 타깃인지 확인한다.
3. **UI-VM 오독** — ui_master 레코드에서 `0xF0~0xF5` 는 옵코드지 글리프 선두바이트가
   아니다. 대사 문법으로 읽으면 없는 글리프를 쓰는 것처럼 보인다.

## fix_leftover_relocate.py — 번역·재배치
번역이 원문보다 길어 제자리에 못 넣는 레코드를 폰트 도너로 옮기고 포인터를
재조준한다. **포인터가 정확히 1개일 때만** 손댄다. 도너는 '아직 원본 폰트 그대로이고
살아있는 레코드가 참조하지 않는 글리프 슬롯'만 쓴다(충돌 시 글자가 깨진다).

## fix_tr_leftover.py — TR ← EX 이식
트레이닝 모드는 EX 의 쌍둥이라 같은 UI 문자열이 EX 에 번역·폭검증된 채로 있다.
TR 레트일 바이트가 일치하는 EX 위치를 찾아(델타 후보 + 유일검색) EX 패치본 바이트를
그대로 가져온다. EX 가 제자리 번역이라 TR 에도 그대로 들어간다.
