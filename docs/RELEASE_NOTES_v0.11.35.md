# v0.11.35 — 유닛 개조 프리징 긴급 수정 (v0.11.34 회귀)

**v0.11.34 를 쓰고 계시면 반드시 이 버전으로 바꿔 주세요.** 제2차·제3차·EX 전부에서
**기체(유닛) 개조를 확정하는 순간 게임이 멈췄습니다.** 제 실수입니다.

## 무엇이 잘못됐나

실행파일마다 **282엔트리짜리 공용 UI 문자열표**가 있습니다(필드상대 s32, 4바이트 비정렬).
이 표의 여덟 엔트리는 레코드의 **시작이 아니라 안쪽**을 겨눕니다. 엔진은
`[ptr[n], ptr[n+1])` 구간을 하나의 런으로 그립니다.

```
idx21 `HP␠`  idx22 `EN␠`  idx23 `운동성␠`  idx24 `장갑␠`  idx25 `한계반응␠`
idx26 = 두 숫자 사이 자리     idx27 = 숫자2 뒤 나머지
```

**idx26 자리는 정확히 2바이트입니다.** 레트일은 반각 두 개(`が` `,`), v0.11.33 은 전각
하나(`이`) — 둘 다 글리프 경계라 문제가 없었습니다. v0.11.34 가 #17a 를 고치면서 거기에
**반각 하나(`-`, 1바이트)** 를 넣는 바람에

```
v0.11.34  0xAD17: 11 f1 f8 …    =  '-' + '으'(f1 f8)의 선두바이트
          idx27 -> 0xAD19 = 전각 글리프 f1 f8 의 **둘째 바이트 0xF8**
```

**0xF8 은 텍스트 VM 의 '치환' 옵코드입니다.** 인자 0xEE 를 폭 0x6E(110)로 읽고, 파라미터
링버퍼에서 꺼낸 길이와 빼서 **부호 없는 카운트다운**을 돌립니다. 길이가 110보다 크면
`2^32 - n` 바이트를 0으로 채우려 들어 그 자리에서 멈춥니다.

무기 개조가 멀쩡했던 건 이 레코드·포인터가 **유닛 개조 확인 메시지 전용**이기 때문입니다.
개조 화면 자체는 다른 자산이라 정상으로 보이고, **확정하는 순간** 이 메시지를 그리다 멈춥니다.

## 어떻게 고쳤나

숫자 사이 자리를 다시 **2바이트**로 만들었습니다 — 반각 `-` + 반각 빈칸.

> 한계반응 240- 250으로 됨.
> 확인?

레트일과 같은 2칸이고 반칸(phase)도 그대로라 뒤따르는 것이 하나도 안 움직입니다.
제보 #23 의 "8200 과 8400 사이에 간격이 있으면 좋겠다" 도 함께 만족합니다.

## 왜 게이트가 못 잡았나

기존 검사는 전부 **레코드를 처음부터** 읽습니다. 그런데 이 표는 레코드 **안쪽**을 겨눕니다.
'레코드 안쪽을 겨누는 포인터가 글리프 경계에 있는가' 를 보는 검사가 하나도 없었습니다.

`audit/verify_ui_runs.py` 에 넣었습니다. 표는 개조 확인 레코드(`HP\0EN\0` 로 시작)를 겨누는
포인터를 씨앗으로 **자기탐색**하므로 실행파일마다 자리가 달라도 알아서 찾습니다.
착지 바이트가 **0xF6 이상이면 실패**(VM 옵코드로 오독), 그 미만이면 경고입니다.

| | 치명 / 경고 |
|---|---|
| 레트일 | 0 / 0 |
| v0.11.33 | 0 / 1 |
| **v0.11.34** | **1 / 1** ← 이번 프리징을 정확히 집는다 |
| v0.11.35 | 0 / 0 |

레트일에서 위반이 0이라는 게 이 불변식이 진짜 엔진 규칙이라는 보증입니다.

## 같이 고친 것

### 글리프가 도너로 회수돼 글자가 깨지던 것 (#25 · #23)

EX·트레이닝 폰트에서 `묵`(0x45A)과 `됨`(0x300) 슬롯이 **도너로 회수돼** 그 자리에
재배치된 텍스트 바이트가 얹혀 있었습니다. 종료 메시지의 `우동 묵고 자야겄다` 와 개조
확인 메시지의 `됨` 이 그래서 깨졌습니다.

원인은 순서입니다 — 종료 메시지(`inject_quit`)와 잔재 교체(`fix_residual_jp`)는 주입기보다
**뒤에** 도는데, 도너 판정은 주입기가 아는 글자만 보고 했습니다. 뒤 단계가 심는 문안의
글리프도 보호 대상에 넣었습니다.

### 지형적응 변경 메시지 (v0.11.28 부터 있던 것)

같은 문자열표의 idx35 자리가 **1바이트**인데 전각 `변`(2바이트)의 선두 바이트만 들어가
있어서, 뒤가 `ヌ경.` 으로 깨져 있었습니다. `지형적응 - 변경.` 으로 바꿔 경계를 맞췄습니다
(멈추지는 않고 글자만 깨지던 건이라 v0.11.34 회귀는 아닙니다).

### EX·트레이닝 버튼 설정 (#23 · #25)

옵션 > 버튼 설정 값 표(45바이트, 4바이트 고정 스트라이드)가 EX·TR 만 주입기 목록에서 빠져
**레트일 그대로**였습니다. ○✕△□ 가 레트일 글리프를 가리켜 한글 폰트에서 `톄톈토톡` 으로
떴습니다. 제2차 번역본을 바이트 그대로 가져왔습니다 →
`없음 / ○ / ✕ / △ / □ / L1 / R1 / L2 / R2 / 시작 / 선택`
