# v0.11.29 — 대사가 통째로 밀리던 진짜 원인 (`B9 03`)

이슈 [#8](https://github.com/snake7594/srwcb-korean-patch/issues/8) 의 **제3차
12~16화 대사 밀림**은 재조준을 놓친 **대사 포인터 옵코드 하나** 때문이었습니다.

## 무엇이 잘못됐나

한글은 원문보다 길어 대사 레코드가 통째로 밀립니다. 그래서 대사를 가리키는
변위를 전부 다시 겨눠야 하는데, 알고 있던 형태는 넷뿐이었습니다.

```
B1/B3/B4 <변위>     — 피연산자가 옵코드 바로 뒤
B6 00    <변위>     — 피연산자가 옵코드+2  (v0.11.18 에서 찾음)
```

여기에 **`B9 03 <변위>`** 라는 같은 꼴이 하나 더 있었습니다. 레트일 세 게임에
**367곳**. 이걸 놓친 대사는 레코드 **중간**을 가리켜, 화자가 사라지고 문장
중간부터 나오다가 결국 원문 바이트가 그대로 보입니다.

세 게임을 전수 조사해 골랐습니다 — 판정 기준은 ① 변위가 레코드 시작을 가리키는
비율이 무작위 기댓값(0.8%)의 수십 배 ② 이미 아는 포인터와 **같은 자리가 아님**
③ 표본을 열어 보면 진짜 대사. 같은 방식으로 `B9 08`·`B6 01` 도 찾았습니다.
`B0 FF`·`BE 01` 은 **탈락**시켰습니다 — 문맥 바이트가 전부 똑같고 일정 간격으로
반복되는 데이터라 우연히 맞은 것이었습니다.

| 형태 | 적중 | 판정 |
|---|---|---|
| `B9 03` | 367/372 (99%) | 채택 |
| `B9 08` | 12/13 | 채택 |
| `B6 01` | 8/14 | 채택 |
| `B0 FF` | 29/198 | 기각(데이터) |
| `BE 01` | 10/166 | 기각(데이터) |

**뒤 단계가 레코드를 옮겨 놓는 문제**도 함께 고쳤습니다. 재조준은 3단계에서
하는데 그 뒤 '잔여 레코드 재배치'가 레코드를 옮겨 다시 어긋났습니다. 레코드를
건드리는 일이 다 끝난 뒤 **한 번 더** 맞춥니다.

## 그 밖에 (제보 #7·#8)

- **선택지 둘째 줄 정렬** — 원문이 첫 줄에만 준 **들여쓰기(반각 한 칸)** 를
  번역이 흘려서 첫 줄만 반 칸 왼쪽으로 붙었습니다. 이제 원문 들여쓰기를 그대로
  살립니다(제3차 10곳, EX 11곳). 첫 줄이 상자를 넘치면 붙이지 않습니다.
- **`유닛능력 / 파일럿능력 / 무기성능표`** — 세 칸의 시작 위치가 레트일과
  어긋나 있었습니다(0/7/15 → **0/8/17**). `무기성능표` 는 `무기성능` 으로
  줄였습니다.
- **`미행동 유닛이19기 있습니다`** — 숫자 앞에 한 칸 띄웠습니다.
- **`출격 유닛 남음`** → **`출격유닛남음`** (붙여쓰기). 전체 폭은 레트일과 같은
  13칸이라 뒤따르는 `12기`·`기력 100`·`LV순` 은 그대로입니다.

## 재발 방지

`audit/verify_image.py` 에 **대사 포인터 서수 검사**를 넣었습니다. '레코드
시작을 가리키는지'만 보면 안 됩니다 — 레코드가 촘촘해서 어긋난 변위도 우연히
어떤 레코드의 시작에 맞습니다. **레트일과 같은 순번의 레코드**를 가리키는지
대조합니다. 이 검사가 이번 367곳을 잡아냈습니다.

## 남은 것

- 제2차 1곳 · EX 4곳의 포인터는 아직 못 맞췄습니다. 둘 다 **이벤트 스크립트 안의
  촘촘한 포인터 표**인데, 변위를 고치면 그 2바이트가 레코드 훑기에서 `0xFF` 로
  읽혀 경계가 움직이고, 다시 계산하면 또 어긋나 수렴하지 않습니다. 검사기가
  이 수를 못박아 두고 **늘어나면 빌드를 세웁니다.**
- 제보 #7 의 **출격/부대표 목록 열 위치**(파일럿명·LV 가 오른쪽으로 밀린 것,
  부대표 유닛명 한 칸 들여쓰기)는 이번에 손대지 못했습니다.
