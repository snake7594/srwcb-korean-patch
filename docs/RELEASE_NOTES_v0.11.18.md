# v0.11.18 — 제3차 대사 꼬임 근본 해결

제3차 슈퍼로봇대전의 대사가 밀리고 화자가 사라지던 문제를 **원인까지 찾아** 고쳤습니다.
그동안은 증상을 우회하느라 번역을 줄여 왔는데, 이번 판에서는 그 축약도 전부 되돌렸습니다.

## 무엇이 문제였나

SCE 이벤트 스크립트의 대사 포인터 명령은 **두 가지 형태**였습니다.

| 형태 | 변위 위치 |
|---|---|
| `B1/B3/B4 <변위16>` | 옵코드 + 1 |
| **`B6 00 <변위16>`** | **옵코드 + 2** |

`B6` 핸들러(점프표 0x1F → `0x800CB1D0`)는 공통 루틴을 부르기 전에 VM 커서를 1 증가시킵니다.
그래서 변위가 한 칸 뒤에 있는데, 재조준기가 앞엣것만 알고 있어서 **제3차 221곳**을
그대로 두었습니다. 그 대사들만 원문 자리를 가리킨 채 남아, 레코드를 옮긴 만큼
밀려서 나왔습니다 — 화자가 사라지고 문장이 중간부터 시작하던 그 증상입니다.

변위가 부호 있는 16비트라는 것도 함께 바로잡았습니다.

## 고친 것

- **대사 포인터 `B6 00 <변위16>` 재조준** — 제3차 221곳, 제2차 13곳, EX 102곳
- 제3차 스크립트 영역 대사 포인터 2,871곳 전부 정상, 재조준 902곳
- **번역 절단 0바이트** — 예산을 맞추느라 34,699바이트를 잘라내던 우회책 제거
- **축약 원복** — 띄어쓰기 제거·화자 이름 생략을 전부 되돌렸습니다
  (대사창 상자 규칙 정정: 줄 수 상한을 원문 줄 수가 아니라 상자 높이 3줄로)
  - `translation/dialogue_box_overrides.json` 97건 → 23건.
    나머지는 예산 때문에 줄여 쓴 것이라 원문 번역으로 되돌렸습니다
- **작전목적(승리/패배조건) 화면 수정** — 제3차는 이 블록이 원문 배치를 벗어나면
  승리조건이 비고 패배조건에 엉뚱한 대사가 들어옵니다. 시나리오 앞머리 블록만
  원문 배치로 고정하고, 대사는 자유롭게 커지도록 분리했습니다
- 레이아웃 엔진이 상자 폭 32 대신 상수 18에서 줄을 접던 버그 수정
- 채움 바이트(0x00)가 줄 폭을 넓혀 상자를 넘기던 문제 수정

## 검증

세 게임 × (컴플리트 박스, 단독판) 6개 이미지 전부:

```
미번역 0 / 대사창 폭·줄 초과 0 / 작전목적 블록 0 / 깨진 레코드 0
```

새 검증 게이트 두 개를 추가해 회귀를 막습니다.
- `check_wrap_width` — 레이아웃이 상자 폭까지 채우는지 자체검사
- `check_objective_block` — 작전목적 블록에 줄이 늘지 않았는지
